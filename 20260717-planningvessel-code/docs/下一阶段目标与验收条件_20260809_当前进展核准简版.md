# 下一阶段目标与验收条件

日期：2026-08-09  
对应总体目标：《高速船型运动预报系统总体目标》  
当前阶段定位：线性高速 2.5D 核心水动力可信化与硬验证闭环

## 1. 当前进展判断

当前项目已经完成“可运行、可诊断、可扩展”的第一轮研究框架，但尚未完成“可验证通过的完整 2.5D 运动预报核心”。

已具备的基础：

1. 已建立 `planing_seakeeping` Python 包、命令行接口、配置读取、波浪输入、频域响应、时域响应、六自由度统一输出、图表和报告生成链路。
2. 已整理 Faltinsen、Ma 2005、Fridsma、Katayama、Delft 372、ITTC 等文献方法，并形成理论、公式、代码和验证输出之间的追溯关系。
3. 已建立 Ma 2005 Wigley III Gate 1 验证体系，可输出八个核心水动力系数的对照、误差、候选路径和失败原因。
4. `numerical_sanity`、`physical_trend_sanity`、`section_bem_numerical_sanity` 当前为 `PASS`，说明基础矩阵、趋势和二维剖面数值链路可作为继续诊断的底座。
5. 示例滑行艇运动计算链路可以运行，能够生成六自由度响应、时域结果、响应幅值算子、图像和报告。

当前关键缺口：

1. Ma 2005 Wigley III 八个核心水动力系数 `A33/B33/A35/B35/A53/B53/A55/B55` 当前仍为 `0/8 PASS`，不能宣称线性 2.5D 核心模型已经通过验证。
2. 固定默认路径 `matched_bie_station_sweep` 下，八系数仍全部失败：

| A33 | 1.000 | 10.186 | 61.243 | FAIL |
| B33 | 2.100 | 9.180 | 22.478 | FAIL |
| A35 | -0.200 | -2.701 | 41.680 | FAIL |

| B53 | -0.100 | -0.252 | 5.069 | FAIL |

| B55 | 0.090 | 1.859 | 131.016 | FAIL |

3. 已排除一批不能进入默认路径的候选，包括 control-row source-only、control-row projection-only、source+projection coupled candidates、简单符号翻转、单一尺度缩放、局部拟合和若干自由面时间层候选。
4. 当前剩余阻塞主要集中在三条链路：
   - `A33/A53`：body potential 到时间压力项的尺度、相位、频率配对和压力恢复链路。
   - `B33/A35/B35/B53`：固定控制面几何输运、压力梯度、端部项和 Eq.31/Eq.32 装配链路。
   - `A55/B55`：纵摇行 `N5/m5`、力臂、Stokes body moment、pressure-gradient moment 和 end-contour moment 链路。
5. SL-7、C1 三体船等公开数字型线仍不足，暂不作为下一阶段硬验收对象。

阶段判断：

> 当前成果是“研究型计算框架与诊断体系已建立”，不是“完整 2.5D 运动预报模型已验证完成”。下一阶段必须优先把线性高速 2.5D 核心水动力模型做实。

## 2. 下一阶段阶段目标

完成线性高速 2.5D 核心水动力 Gate 1 验证闭环，使默认 `matched_bie_station_sweep` 路径在 Ma 2005 Wigley III 算例中稳定、可追溯、可复现地通过八个核心频域水动力系数验证。

必须通过的八个系数为：

```text
A33, B33, A35, B35, A53, B53, A55, B55
```

一句话目标：

> 把当前 2.5D 主线从“能运行、能诊断”推进到“能通过公开基准、能解释误差来源、能支撑后续运动预报和非线性扩展”。

## 3. 阶段边界

本阶段只做以下事情：

1. 以 Ma 2005 Wigley III 为核心硬验收基准。
2. 以 `matched_bie_station_sweep` 作为生产级默认路径。
3. 重点闭合线性 2.5D 的边界积分、自由面匹配、压力恢复、几何输运、端部项和整船装配。
4. 保持示例滑行艇规则波、不规则波和六自由度输出链路可运行。

本阶段不做以下事情：

1. 不把非线性 2D+t、多体船、三体船和水翼船作为生产级模型扩展目标。
2. 不用经验缩放、最终系数拟合、参考结果反推或局部硬调参制造通过。
3. 不把 diagnostic-only 候选提升为默认路径，除非其有明确公式来源、代码证据和八系数整体通过结果。

## 4. 必要条件

为完成下一阶段目标，必须具备以下条件：

1. 固定 Ma 2005 Wigley III 的参考数据、无量纲化方式、频率配对、容差门槛和验证命令。
2. 每一项默认路径修改都必须有公式来源、推导说明、代码位置、数值影响和回归测试。
3. `A33/A53`、`B33/A35/B35/B53`、`A55/B55` 三条阻塞链必须分别形成可执行的闭环审计表。
4. 默认路径不得混入只改善单个系数、只改善子集或无法解释物理来源的候选。
5. 快速回归测试和长耗时 Gate 1 验证必须分层管理，避免日常开发被长耗时流程阻塞。
6. 运动预报示例链路必须保持可用，不能因水动力核心修正破坏输入、输出、图表和报告生成。

## 5. 可验收条件

只有同时满足以下条件，下一阶段才可判定完成。

| 编号 | 验收项 | 通过条件 |
|---|---|---|
| 1 | 默认路径 | 八个核心系数均由 `matched_bie_station_sweep` 默认路径直接计算得到。 |
| 2 | 八系数通过 | `A33/B33/A35/B35/A53/B53/A55/B55` 全部为 `PASS`。 |
| 3 | 误差门槛 | 每个系数的 `gate_error_ratio <= 1.0`，不得用平均误差代替逐项通过。 |
| 4 | 候选纪律 | 经验缩放、最终系数拟合、参考值反推、单项符号试探不得进入默认路径。 |
| 5 | 公式追溯 | 每项默认修正均能追溯到文献公式、推导说明或明确数值离散原则。 |
| 6 | 数值稳定 | 验证输出无未解释的 `NaN`、`Inf`、空表、奇异矩阵和非物理跳变。 |
| 7 | 诊断闭环 | 对失败过的候选给出“保留、排除或待证”的记录，并写入阶段报告。 |
| 8 | 快速回归 | 核心快速测试集通过，至少包括 `tests/test_core.py`、`tests/test_station_2p5d.py`、`tests/test_unified_architecture.py`。 |
| 9 | 全量测试 | `python -m pytest -q` 可复现运行；若耗时过长，必须拆分并记录长耗时门。 |
| 10 | 固定验证 | 固定 Gate 1 验证命令生成完整 CSV、图像和 Markdown 报告。 |
| 11 | 示例运行 | `configs/example_planing.yml` 能生成 `summary.csv`、`rao.csv`、时域 CSV、PNG 图像和 `run_report.md`。 |
| 12 | 六自由度输出 | 输出包含 `surge/sway/heave/roll/pitch/yaw`；迎浪主验证聚焦 `heave/pitch` 和垂向加速度，其他自由度明确标注假设。 |
| 13 | 不规则波复现 | 固定随机种子下，不规则波时域响应的均方根、峰值和统计结果可复现。 |
| 14 | 阶段报告 | 报告清楚说明当前通过项、修正依据、失败候选、剩余风险和后续扩展条件。 |

## 6. 固定验收命令

Gate 1 核心验证：

```powershell
python -m planing_seakeeping validate --benchmark all --out outputs\gate1_linear_2p5d_hard_pass\results --reference-root outputs\matched_bie_provider_gate_probe\reference --ma-hydro-model matched_bie_provider --ma-bem-free-surface-panels 4 --ma-bem-body-panels 8
```

示例运动预报：

```powershell
python -m planing_seakeeping run configs\example_planing.yml --out outputs\gate1_linear_2p5d_hard_pass_motion_demo
```

快速回归：

```powershell
python -m pytest -q tests\test_core.py tests\test_station_2p5d.py tests\test_unified_architecture.py
```

全量回归：

```powershell
python -m pytest -q
```

## 7. 未通过时的封口条件

如果下一阶段仍无法实现八系数全部 `PASS`，不得宣称阶段完成，只能判定为“Gate 1 缺口封口”。封口必须满足：

1. 每个失败系数都有明确误差来源分类。
2. 每个候选修正都有诊断结果和排除理由。
3. 默认路径未被经验拟合或参考值反推污染。
4. 下一步所需资料、公式推导、代码改动或验证数据明确到文件、模块和测试。
5. 阶段报告能让后续开发者继续推进，而不是重新摸索同一批问题。

## 8. 进入后续扩展的条件

只有 Gate 1 通过或严格封口后，才进入下一层扩展：

1. Fridsma 规则波和不规则波滑行艇运动、加速度验证。
2. Katayama 非线性跳跃和峰值移动验证。
3. Sun-Faltinsen 非线性 2D+t 原型。
4. Delft 372 双体船共同边界积分路线。
5. SL-7、C1 三体船或可替代公开型线补充。
6. 水翼、压浪板和控制器接口扩展。
