# 下一阶段阶段目标与验收条件：线性 2.5D 核心 Gate 1 验证闭环

## 1. 当前进展判断

项目已经完成第一轮“可运行、可测试、可扩展、边界清楚”的基础建设，但还没有完成总体目标中最核心的“2.5D 运动预报模型可验证闭环”。

已完成：

1. 已建立 `planing_seakeeping` Python 包、命令行接口、配置读取、规则波/不规则波、频域响应、时域响应、六自由度统一输出、图表和报告链路。
2. 示例滑行艇算例可运行，可输出 `summary.csv`、`rao.csv`、时域结果、图像和 `run_report.md`。
3. 文献与验证体系已接入 Ma 2005、Faltinsen、Journee、Fridsma、Katayama、Delft 372、ITTC 等来源，具备可追溯诊断能力。
4. 最新验证中，`numerical_sanity`、`physical_trend_sanity`、`section_bem_numerical_sanity` 已通过。
5. 最新完整自动化测试曾达到 `236 passed`，说明主程序、测试框架和示例链路整体可用。

当前主要缺口：

1. Ma 2005 Wigley III 八个核心水动力系数 `A33/B33/A35/B35/A53/B53/A55/B55` 当前仍为 `0/8 PASS`。
2. 固定 Gate 1 验证命令仍有硬失败，核心问题集中在 `matched_bie_station_sweep` 的压力恢复、前进速度梯度、固定控制面边界分配、端部项、纵摇力矩和复数相位装配链。
3. 最新 fixed-control-surface end-contour 诊断已排除“直接用固定控制面端部项替换船体端部项”的捷径；下一步必须推导统一的控制体边界/端点分配规则。
4. 因此当前系统可称为“可运行、可诊断的研究框架”，还不能称为“线性 2.5D 核心已硬验证通过的运动预报系统”。

## 2. 下一阶段唯一主目标

完成线性高速 2.5D 核心水动力模型的 Gate 1 硬验证闭环。

具体目标是：在不使用经验缩放、不按参考结果反推系数、不把诊断候选路径混入默认生产路径的前提下，修复或封口 `matched_bie_station_sweep` 默认路径，使 Ma 2005 Wigley III 的八个频域水动力系数 `A33/B33/A35/B35/A53/B53/A55/B55` 达到可验证、可解释、可复现的状态。

一句话目标：

> 把当前“能运行、能诊断”的线性 2.5D 主线，推进为“能硬验证、能解释误差、能支撑后续非线性 2D+t、多体船和水翼扩展”的核心模型。

## 3. 本阶段范围

本阶段纳入：

1. Ma 2005 Wigley III 八系数硬验证。
2. `matched_bie_station_sweep` 默认路径的公式级修复。
3. 时间压力、前进速度压力梯度、固定控制面边界分配、端部项、站位推进、纵摇力矩、复数相位和无量纲化链路审计。
4. Journee 1992 频域复数力、相位和力矩链路作为辅助核对。
5. Katayama 定性趋势失败项的修复或合理重分类，避免阶段范围内残留未解释硬失败。
6. 示例滑行艇规则波、不规则波、六自由度输出链路保持可运行。
7. 测试、验证输出和阶段报告同步更新。

本阶段不纳入：

1. 不开发生产级强非线性 2D+t 自由面边界元模型。
2. 不开发生产级双体船、三体船共同边界积分模型。
3. 不开发生产级水翼、压浪板和控制器模型。
4. 不把 SL-7、C1 三体船或 Delft 372 作为本阶段硬通过对象。
5. 不使用经验拟合、最终系数缩放或参考曲线反推制造通过结果。

## 4. 可验收条件

| 类别 | 验收条件 |
|---|---|
| 默认路径 | 八个核心系数必须由 `provider_route == matched_bie_station_sweep` 的默认路径计算得到。 |
| 八系数硬通过 | `ma2005_wigley_iii_coefficients_comparison.csv` 中 `A33/B33/A35/B35/A53/B53/A55/B55` 全部为 `PASS`，且 `gate_error_ratio <= 1.0`。 |
| 公式可追溯 | 频率、坐标、符号、单位、无量纲化、边界条件、端部项和取舍理由必须写入阶段报告，并能对应到 Ma 2005 / Journee 1992 / Faltinsen 的公式或表格。 |
| 禁止经验污染 | 未通过八系数硬门槛的候选路线必须保持 `candidate_default_gate_eligible=false`，不得进入默认结果。 |
| 控制面闭环 | row-measure、endpoint-forward、端部项、纵摇 `m5` 输运和复数相位必须被同一套规则解释；不能只让单个系数局部变好。 |
| 数值质量 | 验证输出、矩阵、响应幅值、时域响应和统计结果不得出现 `NaN`、`Inf`、空表或未解释异常值。 |
| 验证状态 | `validation_status_by_benchmark.csv` 中本阶段相关硬验证不得保留 `FAIL`；资料不足项可为 `PENDING_REFERENCE_OR_IMPLEMENTATION`，但必须说明缺口。 |
| 示例链路 | `configs/example_planing.yml` 必须可运行，并生成 `summary.csv`、`rao.csv`、时域 CSV、图像和 `run_report.md`。 |
| 六自由度输出 | 时域结果必须包含 `surge/sway/heave/roll/pitch/yaw`；迎浪重点验证 `heave/pitch` 和垂向加速度，其余自由度必须标注模型假设。 |
| 不规则波复现 | 固定随机种子下，不规则波响应的均方根、峰值和统计结果可复现。 |
| 自动化测试 | `python -m pytest -q` 必须全部通过；若未完整运行，必须记录原因、已运行测试和补跑计划。 |
| 阶段报告 | 阶段报告必须包含代码改动、公式依据、验证命令、八系数对照、失败封口、候选排除、剩余风险和下一步建议。 |
