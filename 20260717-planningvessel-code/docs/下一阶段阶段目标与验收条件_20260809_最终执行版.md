# 下一阶段阶段目标与验收条件

日期：2026-08-09  
对应总体目标：《高速船型运动预报系统总体目标》  
阶段定位：线性高速 2.5D 核心水动力模型可信化与硬验证闭环

## 1. 当前进展

项目已经完成第一轮“可运行、可诊断、可扩展”的研究框架建设，但尚未完成“完整 2.5D 核心模型已验证通过”的目标。

已完成内容：

1. 已建立 `planing_seakeeping` Python 包、命令行接口、配置读取、波浪输入、频域响应、时域响应、六自由度统一输出、可视化和报告生成链路。
2. 已整理并接入 Faltinsen、Ma 2005、Fridsma、Katayama、Delft 372、ITTC 等文献方法和验证线索。
3. 已形成 Ma 2005 Wigley III Gate 1 验证体系，能够输出八个核心频域水动力系数的参考值、计算值、误差、状态和诊断信息。
4. 基础数值链路、二维剖面数值诊断、物理趋势检查和示例滑行艇运动预报链路已经具备继续开发的基础。
5. 多体船、三体船、非线性 2D+t 和水翼船模块已有架构预留，但仍属于后续扩展，不应作为当前生产级模型宣称。

1. 默认 `matched_bie_station_sweep` 路径下，Ma 2005 Wigley III 八个核心水动力系数仍为 `0/8 PASS`。

## 2. 下一阶段目标

下一阶段目标是：

> 完成线性高速 2.5D 核心水动力 Gate 1 验证闭环，使默认 `matched_bie_station_sweep` 路径在 Ma 2005 Wigley III 算例中稳定、可追溯、可复现地通过八个核心频域水动力系数 `A33/B33/A35/B35/A53/B53/A55/B55` 的硬验收。

简练表述：

> 把当前 2.5D 主线从“能运行、能诊断”推进到“能通过公开基准、能解释误差来源、能支撑后续运动预报扩展”。

## 3. 阶段边界

本阶段重点做：

1. 固定 Ma 2005 Wigley III 为核心硬验收算例。
2. 固定 `matched_bie_station_sweep` 为生产级默认路径。
3. 闭合线性 2.5D 的边界积分、自由面匹配、压力恢复、几何输运、端部项和整船装配链路。
4. 保持示例滑行艇规则波、不规则波、六自由度输出和报告生成链路可运行。

本阶段暂不做：

1. 不把非线性 2D+t、多体船、三体船和水翼船作为生产级完成目标。
2. 不用经验缩放、最终系数拟合、参考结果反推或局部硬调参制造通过。
3. 不把 `diagnostic-only` 候选提升为默认路径，除非其同时具备公式依据、代码证据和八系数整体验收结果。

## 4. 必要条件

完成下一阶段目标必须满足以下前置条件：

1. Ma 2005 Wigley III 的参考数据、无量纲化方式、频率配对、容差门槛和验收命令必须固定。
2. 每一项默认路径修改必须有文献公式、推导说明或明确数值离散依据。
3. 每一项默认路径修改必须记录代码位置、影响系数、误差变化和回归测试结果。
4. `A33/A53`、`B33/A35/B35/B53`、`A55/B55` 三类失败链路必须分别形成可追溯审计表。
5. 默认模型不得混入只改善单个系数、只改善局部子集或无法解释物理来源的候选。
6. 快速回归测试、长耗时 Gate 1 验证和示例运动预报必须分层执行并保留输出。

## 5. 可验收条件

只有同时满足以下条件，下一阶段才可判定完成：

| 编号 | 验收项 | 通过条件 |
|---|---|---|
| 1 | 默认路径 | 八个核心系数全部由 `matched_bie_station_sweep` 默认路径直接计算得到。 |
| 2 | 八系数通过 | `A33/B33/A35/B35/A53/B53/A55/B55` 全部为 `PASS`。 |
| 3 | 误差门槛 | 每个系数 `gate_error_ratio <= 1.0`，不得用平均误差或部分通过代替逐项通过。 |
| 4 | 公式追溯 | 每项默认修正均能追溯到文献公式、推导说明或明确数值离散原则。 |
| 5 | 候选纪律 | 经验缩放、最终系数拟合、参考值反推、单项符号试探不得进入默认路径。 |
| 6 | 数值稳定 | 验证输出无未解释的 `NaN`、`Inf`、空表、奇异矩阵和非物理跳变。 |
| 7 | 诊断闭环 | 对所有失败过的候选给出“保留、排除或待证”记录，并写入阶段报告。 |
| 8 | 快速回归 | `tests/test_core.py`、`tests/test_station_2p5d.py`、`tests/test_unified_architecture.py` 通过。 |
| 9 | 全量回归 | `python -m pytest -q` 可复现运行；若耗时过长，必须拆分并记录长耗时门。 |
| 10 | Gate 1 输出 | 固定 Gate 1 验证命令生成完整 CSV、图像和 Markdown 报告。 |
| 11 | 示例运行 | `configs/example_planing.yml` 能生成 `summary.csv`、`rao.csv`、时域 CSV、PNG 图像和 `run_report.md`。 |
| 12 | 六自由度输出 | 输出包含 `surge/sway/heave/roll/pitch/yaw`；迎浪主验证聚焦 `heave/pitch` 和垂向加速度，其他自由度明确标注模型假设。 |
| 13 | 不规则波复现 | 固定随机种子下，不规则波时域响应的均方根、峰值和统计结果可复现。 |
| 14 | 阶段报告 | 报告清楚说明通过项、修正依据、失败候选、剩余风险和后续扩展条件。 |

## 6. 固定验收命令

Gate 1 核心验证：

```powershell
python -m planing_seakeeping validate --benchmark all --out outputs\gate1_linear_2p5d_hard_pass\results --reference-root outputs\matched_bie_provider_gate_probe\reference --ma-hydro-model matched_bie_provider --ma-bem-free-surface-panels 4 --ma-bem-body-panels 8
```

示例运动预报：

```powershell
python -m planing_seakeeping run configs\example_planing.yml --out outputs\gate1_linear_2p5d_hard_pass_motion_demo
```

快速回归：

```powershell
python -m pytest -q tests\test_core.py tests\test_station_2p5d.py tests\test_unified_architecture.py
```

全量回归：

```powershell
python -m pytest -q
```

## 7. 未通过时的封口标准

如果八系数仍无法全部 `PASS`，不得宣称阶段完成，只能判定为“Gate 1 缺口封口”。封口必须满足：

1. 每个失败系数都有明确误差来源分类。
2. 每个候选修正都有诊断结果和排除理由。
3. 默认路径未被经验拟合或参考值反推污染。
4. 下一步所需资料、公式推导、代码改动或验证数据明确到文件、模块和测试。
5. 阶段报告能让后续开发继续推进，而不是重新摸索同一批问题。

## 8. 后续扩展进入条件

只有 Gate 1 通过或严格封口后，才进入下一层扩展：

1. Fridsma 规则波和不规则波滑行艇运动、加速度验证。
2. Katayama 非线性跳跃和峰值移动验证。
3. Sun-Faltinsen 非线性 2D+t 原型。
4. Delft 372 双体船共同边界积分路线。
5. SL-7、C1 三体船或可替代公开型线补充。
6. 水翼、压浪板和控制器接口扩展。
