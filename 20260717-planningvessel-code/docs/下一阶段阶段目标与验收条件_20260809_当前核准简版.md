# 下一阶段阶段目标与验收条件

日期：2026-08-09  
对应总体目标：《高速船型运动预报系统总体目标》

## 1. 当前进展判断

当前项目已经完成“高速船型运动预报系统研究框架 v1”的基础建设，但尚未完成“可验证的完整 2.5D 运动预报模型”。

已完成的部分包括：

1. 已建立 `planing_seakeeping` Python 包、命令行接口、配置读取、规则波与不规则波输入、频域响应、时域响应、六自由度统一输出、图表和报告输出链路。
2. 已整理并接入 Faltinsen、Ma 2005、Fridsma、Katayama、Delft 372、ITTC 等文献与验证对象，形成了从理论公式到代码实现、再到验证输出的追溯框架。
3. 基础数值检查、物理趋势检查和二维剖面边界元检查当前可运行，其中 `numerical_sanity`、`physical_trend_sanity`、`section_bem_numerical_sanity` 当前为 `PASS`。
4. 已建立 Ma 2005 Wigley III Gate 1 诊断体系，可输出八个核心水动力系数的误差、候选路径、失败原因和阶段报告。
5. 已对 Eq.23 符号映射、法向定义、源法向方向、A1 文献语义法向、控制面共享未知量约定等关键问题进行诊断；目前没有证据支持用经验符号翻转、整体法向翻转或共享未知量符号转换进入默认路径。

当前关键缺口包括：

1. Ma 2005 Wigley III 八个核心频域水动力系数 `A33/B33/A35/B35/A53/B53/A55/B55` 当前仍为 `0/8 PASS`。
2. `ma2005_wigley_iii_coefficients` 当前仍为 `FAIL`，说明线性 2.5D 核心水动力链路尚未完成可信闭合。
3. `katayama_regular_wave_qualitative_trends` 仍有失败项，不能在 Gate 1 之前把后续非线性运动响应作为可信结论。
4. 全量 `python -m pytest -q` 运行耗时较长，测试体系需要区分快速回归门和长耗时诊断门。
5. SL-7、C1 三体船等公开可用数字型线仍不充分，暂不作为下一阶段硬验收对象。

阶段判断：

> 当前系统是“可运行、可诊断、可继续扩展的研究框架”，但还不是“已验证完成的完整运动预报系统”。下一阶段必须优先把线性高速 2.5D 核心水动力验证做实。

## 2. 下一阶段阶段目标

完成线性高速 2.5D 核心水动力模型 Gate 1 验证闭环，使 `matched_bie_station_sweep` 默认路径能够稳定、可追溯、可复现地通过 Ma 2005 Wigley III 八个核心频域水动力系数验证。

必须通过的八个系数为：

```text
A33, B33, A35, B35, A53, B53, A55, B55
```

本阶段一句话目标：

> 把线性 2.5D 主线从“能运行、能诊断”推进到“能验证、能解释、能支撑后续滑行艇运动预报扩展”。

## 3. 本阶段边界

本阶段只做以下工作：

1. 固定 Ma 2005 Wigley III 为硬验收对象。
2. 固定 `matched_bie_station_sweep` 为生产默认主线。
3. 集中闭合内外域匹配、自由面推进、压力恢复、前进速度项、端部项、力矩臂、相位约定和无量纲化链路。
4. 保持示例滑行艇、规则波、不规则波、六自由度输出和报告链路不被破坏。

本阶段暂不做以下扩展：

1. 不把非线性 2D+t BEM 作为生产内核交付。
2. 不把双体、三体、水翼模型作为硬验收对象。
3. 不用经验缩放、参考结果反推、最终系数拟合或局部符号试探制造通过结果。
4. 不把未验证的占位模型包装成完整物理模型。

## 4. 必要工作条件

为达到本阶段目标，必须满足以下工作条件：

1. 固定 Ma 2005 Wigley III 的参考数据来源、频率匹配方式、无量纲化方式和误差门槛。
2. 每一处默认路径修改都必须能追溯到文献公式、推导说明或明确的数值离散原则。
3. 每一个候选修正都必须记录公式来源、代码位置、数值影响、是否进入默认路径、未进入默认路径的原因。
4. 保持诊断候选与生产默认路径分离，避免把“试探有效”的参数混入默认模型。
5. 将测试体系分为快速回归门和长耗时 Gate 1 诊断门。
6. 任何扩展模块必须服从 Gate 1，不得绕过核心 2.5D 验证直接扩展。

## 5. 可验收条件

只有同时满足以下条件，才能判定下一阶段完成：

| 编号 | 验收项 | 通过条件 |
|---|---|---|
| 1 | 默认路径 | 八个核心系数均由 `matched_bie_station_sweep` 默认路径直接计算得到。 |
| 2 | 八系数硬通过 | `A33/B33/A35/B35/A53/B53/A55/B55` 全部为 `PASS`。 |
| 3 | 误差门槛 | 每个系数的 `gate_error_ratio <= 1.0`，不得用平均误差替代逐项通过。 |
| 4 | 公式追溯 | 每项代码修正均能追溯到文献公式、理论推导或明确数值离散原则。 |
| 5 | 候选纪律 | 经验缩放、符号试探、参考值反推、最终系数拟合不得进入默认路径。 |
| 6 | 数值稳定 | 验证输出无未解释的 `NaN`、`Inf`、空表、奇异矩阵或非物理跳变。 |
| 7 | 快速回归 | 核心快速测试集通过，并记录命令、耗时和结果。 |
| 8 | 长耗时诊断 | Gate 1 长耗时诊断可复现运行，并生成完整 CSV、图像和 Markdown 报告。 |
| 9 | 示例链路 | `configs/example_planing.yml` 可生成 `summary.csv`、`rao.csv`、时域 CSV、PNG 图像和 `run_report.md`。 |
| 10 | 六自由度输出 | 输出包含 `surge/sway/heave/roll/pitch/yaw`；迎浪主验证聚焦 `heave/pitch` 和垂向加速度，其余自由度明确标注模型假设。 |
| 11 | 不规则波复现 | 固定随机种子下，不规则波响应的均方根、峰值和统计结果可复现。 |
| 12 | 阶段报告 | 报告必须包含误差状态、修正依据、通过项、失败项、候选排除、剩余风险和下一步建议。 |

## 7. 未通过时的封口条件

如果下一阶段仍不能达到八个系数全部 `PASS`，不得宣称 Gate 1 完成，只能判定为“Gate 1 缺口封口”。封口必须满足：

1. 每个失败系数都有明确误差来源分类。
2. 每个候选修正都有“保留、排除或待证”的结论。
3. 默认路径未被经验拟合、符号试探或参考值反推污染。
4. 下一步所需资料、推导或代码改动明确到文件、公式、模块或测试。

## 8. 进入后续阶段的条件

只有 Gate 1 通过或完成严格封口后，才进入后续扩展：

1. Fridsma 规则波与不规则波滑行艇运动、加速度验证。
2. Katayama 非线性跳跃和峰值移动验证。
3. Sun-Faltinsen 型非线性 2D+t 原型。
4. Delft 372 双体船共同边界积分路线。
5. SL-7、C1 三体船或替代公开型线补充。
6. 水翼、压浪板和控制器接口扩展。
